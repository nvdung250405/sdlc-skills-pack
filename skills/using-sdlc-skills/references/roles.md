# Role → skill map

| Role | Owns | Primary skills | Main outputs |
|---|---|---|---|
| Orchestrator | Selects workflow and prevents stage skipping | `using-sdlc-skills`, `task-handoff` | task handoff, workflow route |
| Product / Business Analyst | Problem framing, scope, business rules, requirements | `interview-me`, `idea-refine`, `spec-driven-development`, `pm-user-story` | opportunity brief, PRD, user stories, BDD AC |
| System / Software Architect | System structure, quality attributes, cross-cutting decisions | `software-architecture`, `api-and-interface-design`, `database-design`, `documentation-and-adrs` | architecture, API contracts, ADRs, database schemas |
| UX / Frontend Engineer | User flows, accessible UI components, responsive layout | `frontend-ui-engineering` | production frontend components, accessible DOM |
| Tech Lead / Planner | Feature slicing, ordering, dependencies and tasks | `planning-and-task-breakdown` | implementation plan, tasks breakdown |
| Developer | Correct implementation in verified slices | `incremental-implementation`, `test-driven-development`, `source-driven-development`, `git-workflow-and-versioning`, `code-simplification` | code, unit tests, commits, refactored modules |
| QA / SDET | Independent requirement-level verification | `verification-before-completion`, `webapp-testing`, `api-contract-testing`, `k6-load-testing` | acceptance report, Playwright E2E, contract tests, load metrics |
| Reviewer | Finds correctness, maintainability and regression issues | `code-review-and-quality` | prioritized findings with severity and evidence |
| Security | Threats, unsafe trust boundaries, secure defaults | `security-and-hardening`, `auth-implementation-patterns` | threat model, auth tokens, RBAC policies |
| DevOps / SRE | CI/CD, containerization, release safety, telemetry | `ci-cd-and-automation`, `shipping-and-launch`, `observability-and-instrumentation`, `docker-expert` | CI/CD pipelines, Dockerfile, alert rules, release notes |
| Growth / Data Analyst | Product telemetry taxonomy and experiment tracking | `analytics` | tracking plan, event schemas, experiment briefs |
