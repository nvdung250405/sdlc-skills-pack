# SDLC Pack Complete Routing Table

This reference contains the exhaustive 38-route intent matching table for the SDLC skill pack. The pack router (`using-sdlc-skills/SKILL.md`) references this document for detailed lookups while keeping its core prompt footprint lean.

---

## Skill Availability & Graceful Fallback Protocol

Before invoking an optional or specialist skill listed below:
1. **Check Disk Availability**: Verify the skill directory exists under `skills/` or `extras/` (or the agent's installed skills directory).
2. **If Installed**: Load and execute the specialized skill instructions.
3. **If Not Installed (e.g., Core profile or lean runtime)**:
   - Do **NOT** fail silently or claim the specialist tool ran.
   - Fall back to the manual or general engineering procedure specified in the active workflow (e.g., run test suite via `python -m unittest` or project runner; perform visual inspection; audit code using canonical checklists).
   - Log the fallback and any verification limitation in `.agent/tasks/<task-id>.md`.

## Complete Intent Routing Matrix

| User Intent / Change Type | Recommended Route | Primary Workflow | Fallback If Extras Unavailable |
|---|---|---|---|
| Idea unclear or business problem unknown | `interview-me` → `idea-refine`; use `customer-research` for user insight synthesis and `pm-product-spec` once problem/assumptions are grounded. | None (intake) | Ask clarifying questions directly; scaffold `docs/discovery/[initiative]/opportunity-brief.md` manually. |
| New product or major initiative | Follow `workflows/full-sdlc.md`: `interview-me` / `idea-refine` as needed → `pm-product-spec` → optional `pm-spec-quality-audit` → formal `requirements-engineering` only when SRS/FR/NFR/UC/RTM are justified → `software-architecture` when system boundaries or material quality attributes need design. | `workflows/full-sdlc.md` | Core skills handle all major stages (`pm-product-spec`, `software-architecture`, `planning-and-task-breakdown`). |
| New user-facing feature | Follow `workflows/feature-loop.md`: `pm-product-spec` if product intent/scope is not already defined → `pm-user-story` to author Story and Given/When/Then AC in canonical feature spec → `pm-spec-quality-audit` for significant/ambiguous/high-risk specs → `spec-driven-development` to structure spec/plan/tasks when useful → architecture/API/UI skills only when the change warrants them → `planning-and-task-breakdown` → implementation and verification. | `workflows/feature-loop.md` | Fully supported in Core profile. |
| Small, clear feature/change | Follow `workflows/quick-change.md`: Read repository guidance/context → `spec-driven-development` only if a feature spec is missing or behavior is ambiguous → `incremental-implementation` and `test-driven-development` when behavior changes → `verification-before-completion` → `code-review-and-quality` as risk warrants. | `workflows/quick-change.md` | Fully supported in Core profile. |
| Bug or unexpected behavior | Follow `workflows/bug-fix.md`: `systematic-debugging` → reproduce and isolate the root cause → regression test/TDD where practical → smallest fix → project verification → `verification-before-completion` and review. | `workflows/bug-fix.md` | Fully supported in Core profile. |
| Refactor / Code simplification | Follow `workflows/refactoring.md`: establish characterization tests → `improve-codebase-architecture` and `codebase-design` for deep modules → `code-simplification` micro-steps → regression verification. | `workflows/refactoring.md` | Use `code-simplification` (Core) and manual module decomposition. |
| Architecture review & deep modules | `software-architecture` for component boundaries and C4 models → `codebase-design` for deep module design → `domain-modeling` for ubiquitous language and glossaries → `documentation-and-adrs` for decisions with trade-offs. | `workflows/full-sdlc.md` | Use `software-architecture` and `documentation-and-adrs` (Core). |
| Codebase architecture improvement | `improve-codebase-architecture` to scan for shallow modules, leaky abstractions, or architectural drift → propose incremental remedies. | `workflows/refactoring.md` | Audit code against deep module principles and record findings in ADR. |
| Tracer-bullet ticket breakdown | `to-tickets` to convert plans or specifications into self-contained tracer-bullet task tickets declaring explicit dependency edges. | `workflows/feature-loop.md` | Break tasks manually into `docs/features/<feature-id>/tasks.md` using `planning-and-task-breakdown` (Core). |
| API/schema/integration change | `api-and-interface-design` plus `software-architecture` when system boundaries or major data ownership change. **Contract-First Rule:** Always scaffold executable contracts (`contracts/openapi.yaml`, `contracts/asyncapi.yaml`, `contracts/stomp-websocket.yaml`, `contracts/service.proto`, `contracts/schema.graphql`, `contracts/data-contract.json`); **never** generate unstructured prose markdown such as `api.md` → `api-contract-testing` for wire-level consumer-provider compatibility and regression fixtures → ADR only for meaningful trade-offs → plan and implementation. | `workflows/feature-loop.md` | Run `scripts/verify_contracts.py` to validate contract syntax. |
| System / schema / API migration | Follow `workflows/deprecation-and-migration.md`: use `deprecation-and-migration` and `database-design` for 4-phase Expand/Contract zero-downtime transition; coordinate with `code-simplification`. | `workflows/deprecation-and-migration.md` | Execute 4-phase expand/contract manually following `templates/delivery/deprecation-notice.md`. |
| Database schema / persistence design | `database-design` to select database/ORM, design normalized tables, indexing strategy and safe migrations; coordinate with `software-architecture`. | None | Core skill (`database-design`). |
| React / Next.js web application | `vercel-react-best-practices` for eliminating waterfalls, optimizing RSC boundaries, bundle size, and rendering performance; coordinate with `frontend-ui-engineering` and `frontend-design`. | None | Follow React/Next.js official docs via `source-driven-development` (Core). |
| Multi-agent / subagent orchestration | `subagent-driven-development` to orchestrate parallel implementation streams with isolated subagents and independent review gates. | None | Implement sequentially in small slices with `incremental-implementation` (Core). |
| Authentication / authorization flow | `auth-implementation-patterns` for session/token lifecycles, OAuth2/OIDC boundaries and RBAC policy enforcement; coordinate with `security-and-hardening`. | None | Follow `security-and-hardening` (Core) and canonical security checklist. |
| Threat modeling & security analysis | `threat-model-analyst` for STRIDE threat modeling, data-flow diagrams, and abuse cases; coordinate with `security-and-hardening`. | None | Scaffold `templates/governance/threat-model.md` and assess STRIDE categories manually using `security-and-hardening` (Core). |
| Secrets & CI credential handling | `secrets-management` for secret stores, workload identity and credential rotation; coordinate with `ci-cd-and-automation`. | None | Use `ci-cd-and-automation` (Core) and `.env.example` templates. |
| Performance profiling & optimization | Follow `workflows/performance-tuning.md`: baseline benchmark with `k6-load-testing` / DevTools → bottleneck profiling (`database-design`, profilers) → surgical fix with `performance-optimization` → comparative before/after verification. | `workflows/performance-tuning.md` | Run localized benchmark scripts, profile DB queries with EXPLAIN, and check `shared/references/performance-checklist.md`. |
| Dependency / library / CVE upgrade | Follow `workflows/dependency-upgrade.md`: audit changelogs / CVEs with `security-and-hardening` → isolated workspace via `using-git-worktrees` → update manifests & lockfiles → fix breaking changes → verify regressions. | `workflows/dependency-upgrade.md` | Fully supported in Core profile. |
| Container / platform orchestration | `docker-expert` for container optimization/hardening; `kubernetes-architect` for cluster orchestration and GitOps; `terraform-specialist` for IaC module design and state. | None | Follow official docs via `source-driven-development` (Core) and `ci-cd-and-automation` (Core). |
| Service mesh & distributed tracing | `service-mesh-observability` for Istio/Linkerd telemetry, distributed tracing, envoy metrics, and communication SLOs. | None | Instrument OpenTelemetry traces and structured logging with `observability-and-instrumentation` (Core). |
| Cloud cost governance & FinOps | `cost-optimization` for resource rightsizing, spend anomaly detection, tagging enforcement, and multi-cloud cost reduction. | None | Record FinOps cost implications in ADRs using `documentation-and-adrs` (Core). |
| Accessibility / screen-reader audit | `screen-reader-testing` for screen-reader and ARIA accessibility verification; coordinate with `webapp-testing`. | None | Inspect semantic HTML, ARIA landmarks, and keyboard navigation manually. |
| Visual & web design review | `web-design-guidelines` for typography, spacing, responsive layout, and modern CSS guidelines; `frontend-design` for visual aesthetic direction. | None | Audit against design tokens and responsive breakpoints manually. |
| Product analytics & experimentation | Follow `workflows/experimentation-loop.md`: `analytics` for event tracking taxonomy and funnel metrics; `ab-testing` for hypothesis formulation, variant split, and statistical significance. | `workflows/experimentation-loop.md` | Scaffold `templates/governance/experiment-brief.md` and define metrics manually. |
| Pre-commit hooks & agent guardrails | `setup-pre-commit` for pre-commit hook automation; `git-guardrails-claude-code` for safe autonomous git operations. | None | Configure git hooks manually using `git-workflow-and-versioning` (Core) and shell scripts. |
| AI prompt & MCP server authoring | `writing-for-agents` for crafting high-leverage LLM instructions; `mcp-builder` for constructing Model Context Protocol tools; `skill-authoring` for pack maintenance. | None | Follow official MCP SDK documentation via `source-driven-development` (Core). |
| Technical document authoring | `doc-coauthoring` for collaborative technical writing; `writing-guidelines` for concise editorial standards; `documentation-and-adrs` for architecture records. | None | Use `documentation-and-adrs` (Core) and standard templates. |
| Formal requirements or compliance-heavy system | `requirements-engineering` owns SRS/FR/NFR/use cases/RTM as appropriate; then architecture and feature spec. Never force this flow on a simple bug or small feature. | `workflows/full-sdlc.md` | Fully supported in Core profile. |
| Spec/PRD/Story audit | `pm-spec-quality-audit`; for technical cross-document consistency manually follow canonical links and requirement IDs. Do not change code unless asked. | `workflows/feature-loop.md` | Fully supported in Core profile. |
| Security-sensitive change | Pull security considerations into requirements/design, then `security-and-hardening` during implementation/review; record unmitigated risks and require appropriate approval. | Any active workflow | Fully supported in Core profile (`security-and-hardening`, `references/security-checklist.md`). |
| Web UI runtime verification | Choose `webapp-testing` for Playwright automation or `browser-testing-with-devtools` for DevTools/MCP inspection. Use both only when they supply distinct needed evidence. | `workflows/feature-loop.md` | Run unit/DOM tests with jsdom or browser component tests. |
| Release / deployment | `verification-before-completion` → `code-review-and-quality` and `security-and-hardening` as applicable → `ci-cd-and-automation` → `shipping-and-launch` → `observability-and-instrumentation`; production/destructive operations require approval. | None | Fully supported in Core profile. |
| Production incident | Follow `workflows/incident-response.md` first to mitigate/restore; only then use `systematic-debugging` for root cause and regression work. | `workflows/incident-response.md` | Fully supported in Core profile (`systematic-debugging`, `verification-before-completion`). |
| Transfer between sessions/agents | Follow `workflows/agent-handoff-contract.md`: `task-handoff` first; use `using-git-worktrees` when an isolated workspace is appropriate; read linked authoritative files, not copied summaries alone. | `workflows/agent-handoff-contract.md` | Fully supported in Core profile. |
| Finish a development branch | `verification-before-completion` → `code-review-and-quality` → `git-workflow-and-versioning`; follow repository merge/PR policy. | Any active workflow | Fully supported in Core profile. |
